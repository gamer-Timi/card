信息4：
下面是一套**只依赖 TinyWebDB**、适合休闲回合制游戏的匹配方案。核心原则：**不要让双方都去“抢着标记已匹配”，而是让房主做唯一裁判**；否则两个人同时改同一间房，会双人抢同一局。

统一前缀：**`timicard_`**。

## 一、Key 设计

| Tag | 谁写 | 用途 | Value |
|---|---|---|---|
| `timicard_room_<roomId>` | 房主 | 房间状态（唯一权威） | JSON |
| `timicard_join_<roomId>_<guestId>` | 加入者 | 申请加入 | `{"guest":"...","t":...}` |
| `timicard_move_<roomId>_<seq>` | 加入者 | 走子请求 | `{"player":"...","move":...,"t":...}` |
| `timicard_presence_<roomId>_<playerId>` | 双方 | 心跳/在线 | `{"t":...}` |
| `timicard_result_<roomId>` | 房主 | 可选，保存结果 | JSON |

房间 JSON：

```json
{
  "roomId": "r...",
  "host": "h...",
  "guest": "",
  "status": "open",
  "createdAt": 1790000000000,
  "updatedAt": 1790000000000,
  "seq": 0,
  "turn": "host",
  "board": [],
  "winner": ""
}
```

- `status`：`open` → `playing` → `finished` / `abandoned`
- `seq`：状态版本号，双方只接受比自己大的 `seq`
- `turn`：`host` / `guest`

## 二、匹配流程

### 1. 房主开房

```text
1. 生成 roomId
2. update timicard_room_<roomId> = {status:"open", host:我, ...}
3. 每 1.5~2 秒 search timicard_join_<roomId>_
4. 每 5 秒 update 一次房间的 updatedAt（心跳）
```

### 2. 加入者找房

```text
1. search timicard_room_，翻页，过滤：
   - status === "open"
   - updatedAt 在 20 秒内（没超时）
2. 找到就挑一间，写：
   update timicard_join_<roomId>_<guestId> = {guest:我, t:now}
3. 每 1.5~2 秒 get timicard_room_<roomId>
4. 看到 guest === 我 且 status === "playing" → 开局
```

### 3. 房主接受

```text
1. 读到 join 申请
2. 只选一个（最早/随机）
3. update 房间：{guest:选中的, status:"playing", updatedAt:now}
4. 删除这间房其他 join tag
5. 房主开始游戏
```

关键点：

- **只有房主写 `timicard_room_`**；
- 加入者只写 `timicard_join_`，不直接改房间；
- 因此不会出现“两个人同时把同一间房标成 matched”；没被选中的加入者看到 `guest` 不是自己，就回去重新找房。

### 4. 没找到房

加入者也变成房主：

```text
search 不到 open 房 → 自己 create
之后就是“房主流程”，等别人 join
```

也就是你说的“自己开一个，然后隔一段时间搜一次，直到匹配完成”。

## 三、回合制走子

房主是唯一权威，加入者只提交请求。

### 加入者走子

```text
1. 本地先校验：轮到我、seq 是最新
2. update timicard_move_<roomId>_<seq> = {player:guest, move:..., t:now}
3. 等房主处理
```

### 房主处理

```text
1. 每 1.5~2 秒 search timicard_move_<roomId>_
2. 校验：
   - 是不是 guest 的回合
   - seq 是否等于当前 seq
   - move 是否合法
3. 应用到 board
4. seq++，turn 切换
5. update timicard_room_<roomId> = 新状态
6. delete 已处理的 move tag
```

### 房主自己走子

房主直接改房间状态，`seq++`、换 turn，不需要写 move tag。

### 加入者刷新

```text
每 1.5~2 秒 get 房间
如果 seq > 本地 seq → 应用新状态
如果 turn 变成自己 → 可以走
```

## 四、状态机

```text
open
  ├─ 房主接受 join → playing
  ├─ 超时/房主取消 → abandoned
  └─ 房主离开 → 过期

playing
  ├─ 一方胜利/认输 → finished
  ├─ 60 秒无操作/心跳 → abandoned
  └─ 房主掉线 → 加入者超时退出

finished
  └─ 保留结果几分钟 → 删除
```

## 五、轮询与超时

| 角色 | 轮询内容 | 频率 |
|---|---|---|
| 房主 | join 申请 | 1.5~2 秒 |
| 房主 | move 请求 | 1.5~2 秒 |
| 加入者 | 房间状态 | 1.5~2 秒 |
| 双方 | 心跳 | 5 秒 |
| 双方 | 页面重新可见 | 立即刷新一次 |

- 网络失败：2s → 4s → 8s 退避，别 200ms 一次；
- 页面切后台：暂停轮询，回来立即拉一次；
- `open` 房 `updatedAt` 超过 20 秒视为死房，忽略/删除；
- `playing` 对手 60 秒没心跳/没更新，判掉线。

## 六、清理

- 接受 join 后，删除其他 join；
- 处理 move 后，删除对应 move；
- 每局结束：
  - 房间改 `finished`，写结果；
  - 删除双方 presence、join、move；
  - 结果保留 2~5 分钟后删除房间；
- 房主开新房时，顺手扫一遍 `timicard_room_`，删掉超过 1 小时的 `open/finished` 房。

## 七、API 调用示例

```js
// 封装
async function tdb(action, params = {}) {
  const body = new URLSearchParams({
    user: 'computor',
    secret: '58787c39',
    action,
    ...params
  });
  const res = await fetch('https://tinywebdb.appinventor.space/api', {
    method: 'POST',
    body
  });
  const text = await res.text();
  return text ? JSON.parse(text) : {};
}

// 开房
await tdb('update', {
  tag: 'timicard_room_' + roomId,
  value: JSON.stringify(room)
});

// 找房：单页最多 100 条，要翻页
const page = await tdb('search', {
  no: '1',
  count: '100',
  tag: 'timicard_room_',
  type: 'tag'
});
const rooms = Object.keys(page)
  .filter(k => k.startsWith('timicard_room_'))
  .map(k => JSON.parse(page[k]));

// 申请加入
await tdb('update', {
  tag: 'timicard_join_' + roomId + '_' + guestId,
  value: JSON.stringify({ guest: guestId, t: Date.now() })
});

// 读房间
const got = await tdb('get', { tag: 'timicard_room_' + roomId });
const raw = got['timicard_room_' + roomId];
const room = raw && raw !== 'null' ? JSON.parse(raw) : null;
```

## 八、为什么不直接“搜到空房就标记 matched”

因为没有原子操作：

```text
A 读到 room.status = open
B 也读到 room.status = open
A update status = matched
B update status = matched
→ 两个人都以为自己匹配成功
```

TinyWebDB 没有“只有还是 open 才允许写”的 CAS。

所以改成：

```text
A、B 都只写 join 申请
房主一个人读申请、只接受一个、只写一次房间状态
```

这样只有一个写者，天然避免双抢。

## 九、这套方案的边界

- 延迟：1.5~3 秒，适合棋类、卡牌、回合制；不适合实时动作；
- 房主掉线：加入者超时退出，没有“房主迁移”；
- 房主可以作弊：房间状态是房主写的；
- `secret` 在前端可见：任何人能改/删 `timicard_` 记录；
- `search` 单页最多 100 条：开放房间多时要翻页 + 及时清理；
- 免费接口高频轮询会被限速：人多了要换 Firebase / Supabase / Cloudflare 等。
